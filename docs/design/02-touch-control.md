# 테슬라 화면에서 아이폰 터치 조작

조사일: 2026-10-27

## 결론

**앱만으로는 불가능하지만, 저렴한 블루투스 보드(ESP32, 약 1만 원)를 하나 추가하면 가능하다.** 탈옥이나 맥 없이, 앱스토어 앱 그대로 동작한다.

## 왜 앱만으로는 안 되나

- iOS에는 다른 앱에 터치를 주입하는 공개 API가 없다.
- 유일한 공식 경로는 XCTest(WebDriverAgent)인데, 맥의 Xcode로 실행해야 하고 개발자 서명이 필요하며 화면이 잠기면 죽는다. 개인 실험용으로만 가능하고 배포는 불가능하다.
- 탈옥, 비공개 API는 제외.

## 가능한 방법: 블루투스 마우스로 위장 + AssistiveTouch

iOS는 **AssistiveTouch를 켜면 블루투스 마우스를 지원**한다(iOS 13+). 화면에 포인터가 생기고 클릭하면 그 위치를 터치한 것과 같다. 이 경로는 Apple이 접근성 기능으로 공식 지원하는 것이다.

그래서 ESP32를 "블루투스 마우스"로 만들고, 테슬라 화면에서 누른 좌표를 ESP32가 마우스 동작으로 바꿔서 아이폰에 보낸다.

```
테슬라 화면 터치 (canvas 좌표)
   │ WebSocket
   ▼
아이폰 방송 확장 (좌표를 아이폰 화면 좌표로 변환)
   │ Wi-Fi (ESP32도 같은 핫스팟에 접속)
   ▼
ESP32 (Wi-Fi로 명령 수신 → BLE HID 마우스로 동작)
   │ Bluetooth LE HID
   ▼
아이폰 AssistiveTouch 포인터 이동 + 클릭 = 터치
```

- ESP32는 Wi-Fi와 블루투스를 동시에 쓸 수 있다. 핫스팟에 Wi-Fi로 붙어서 명령을 받고, 아이폰에는 블루투스 마우스로 연결된다.
- 아이폰 앱이 블루투스를 직접 다루지 않아도 된다. 방송 확장에서 CoreBluetooth를 쓸 수 있는지 불확실하기 때문에 이 구조가 안전하다.
- 전원은 테슬라 USB 포트에서 받는다.
- 이미 같은 방식으로 아이폰을 원격 조작하는 오픈소스가 여럿 있다: [esp32-iphone-agent](https://github.com/onehumanbeing/esp32-iphone-agent), [esp32-iphone-agent-ble](https://github.com/Chsengni/esp32-iphone-agent-ble), [Iphone-control-for-social-media](https://github.com/dovydaskel/Iphone-control-for-social-media), [VKCOM devicehub ESP32 문서](https://github.com/VKCOM/devicehub/blob/master/doc/ios-docs/esp32.md)

## 핵심 난제: 좌표 맞추기

마우스는 "어디로"가 아니라 "얼마나 움직여"만 보낸다. iOS에서 절대 좌표 HID가 동작하는지는 자료가 엇갈린다([Apple 포럼](https://developer.apple.com/forums/thread/652700)에서는 BLE 절대 좌표가 안 움직였다는 보고, USB에서는 된다는 보고도 있음).

해결 방법(기존 프로젝트들이 쓰는 방식):
1. **모서리 원점 맞추기**: 왼쪽 위로 크게 움직여서 포인터를 화면 모서리에 붙인다. 이제 위치를 확실히 안다.
2. **추적**: 이후 이동량을 계속 더해서 현재 위치를 추정한다.
3. **보정**: 오차가 쌓이면 다시 모서리로 보낸다. AssistiveTouch 추적 속도를 고정값으로 두고, 이동량 대비 실제 픽셀 비율을 처음에 한 번 측정한다.
4. **영상으로 확인(선택)**: 미러링 영상에 포인터가 찍힌다면 그걸로 위치를 실측해서 보정할 수 있다. 포인터가 화면 녹화에 찍히는지는 확인 필요.

## 지원 가능한 동작

| 동작 | 가능 여부 | 방법 |
|---|---|---|
| 탭 | 가능 | 이동 후 클릭 |
| 길게 누르기 | 가능 | 버튼 누른 채 유지 |
| 드래그, 지도 이동 | 가능 | 버튼 누른 채 이동 |
| 스크롤 | 가능 | 마우스 휠 |
| 핀치 줌 | 어려움 | 포인터가 하나뿐. 지도 앱의 줌 버튼이나 두 번 탭으로 대체 |
| 홈, 앱 전환 | 일부 | AssistiveTouch 메뉴나 버튼 매핑 활용 |
| 글자 입력 (목적지 검색) | 가능성 있음 | ESP32를 키보드로도 동작시켜 테슬라 키보드로 친 글자를 전송. 한글은 두벌식 키코드로 변환. 단, iOS가 복합 장치의 Shift를 무시했다는 보고가 있어 쌍자음(ㄲ, ㅆ 등) 확인 필요 |

## 단점과 위험

- **추가 장치가 필요**하다. 키트로 판매하거나 DIY 안내를 제공해야 한다.
- **처음 설정**: AssistiveTouch 켜기, ESP32 블루투스 페어링, 추적 속도 고정.
- **지연**: 탭마다 이동 시간이 있다. 매번 원점을 맞추면 더 느려지므로 추적 위주로 하고 가끔만 보정한다.
- **화면에 포인터가 항상 보인다.** 일정 시간 뒤 자동으로 숨기는 옵션이 있다.
- **블루투스 키보드가 연결되면 폰의 화면 키보드가 숨는다.** 키보드 기능은 켜고 끌 수 있게 한다.
- **iOS 업데이트에 따라 동작이 바뀔 수 있다.**

## 하드웨어 없이 불편을 줄이는 보조 방안

- **Siri 음성**: "티맵으로 집 안내해줘" 같은 명령은 지금도 가능하다. 안내 문서에 포함.
- **자주 가는 목적지 단축어**: 메인 앱에서 단축어를 미리 만들어 두는 기능.

## 개발 순서 제안

1. 미러링 MVP 먼저 (기존 1~2단계)
2. ESP32 프로토타입: BLE 마우스로 아이폰 포인터 이동, 클릭 확인
3. 원점 맞추기와 좌표 보정 알고리즘, 정확도 측정 (목표: 오차 10px 이내)
4. Wi-Fi 연결과 테슬라 터치 연동
5. 키보드(한글 입력) 실험

## 보드 선택

차량 배선 작업은 필요 없다. 테슬라 USB 포트에 케이블로 꽂아 전원만 받는다. 펌웨어는 처음에 PC로 한 번 굽는다.

| 보드 | Wi-Fi | BLE HID | 비고 |
|---|---|---|---|
| ESP32 DevKitC V4 (오리지널 ESP32) | **2.4GHz만** | 가능 (BLE 4.2) | 프로토타입용. 아이폰 핫스팟 "호환성 최대화"를 켜야 접속 가능 → 테슬라도 2.4GHz로 붙어서 미러링 대역폭이 줄어든다 |
| ESP32-C3 / ESP32-S3 | 2.4GHz만 | 가능 (BLE 5) | 위와 같은 제약 |
| **ESP32-C5** | **2.4GHz + 5GHz** | 가능 (BLE 5) | 최종 권장. 핫스팟 5GHz 유지 가능. DevKitC-1 약 $15 |

- 아이폰 핫스팟은 한 번에 한 대역만 쓴다. 호환성 최대화를 켜면 2.4GHz, 끄면 5GHz(iPhone 12 이상).
- Apple 문서상 핫스팟은 **90초 동안 트래픽이 없는 기기를 자동으로 끊는다.** ESP32는 주기적으로 하트비트를 보내야 한다.
- DevKitC V4는 마이크로 USB 포트인 제품이 많으므로 테슬라 USB-C에 맞는 케이블이 필요하다(데이터 지원 케이블이면 PC 펌웨어 업로드에도 사용 가능).

## 실측 (2026-10-27, ESP32 DevKitC V4 + iPhone 14 Pro, 집에서)

펌웨어 `firmware/tessync-touch`(BLE HID 마우스, USB 시리얼 명령), 맥 쪽 `tools/touch-bridge.py`.

- **BLE 마우스 연결과 포인터 이동: 동작한다.** 페어링은 설정 > 블루투스에서 "Tessync Touch" 선택, AssistiveTouch 켜기.
- **왼쪽 위 모서리로 보내기(원점 맞추기): 동작한다.**
- **포인터가 화면 방송(ReplayKit) 프레임에 찍힌다.** 회색 원(RGB 약 148,149,151), 590x1280 프레임에서 지름 약 27px. 밝은 배경 위에서는 색과 크기로 바로 검출된다. 글자 위에 겹치면 검출이 어렵다.
- 추적 속도 최저에서 이동량 1당 약 0.9~1.1px(프레임 기준, 약 0.6~0.7pt). 기본 속도에서는 약 2배.
- **같은 이동량이라도 실제 이동 거리가 들쭉날쭉하다.** x로 20씩 6번: 28, 17, 17, 7, 19, 20px. 한 번에 120: 131px. 보고서 간격(8ms)이 BLE 연결 간격보다 짧아 합쳐지거나 버려지는 것, 또는 iOS 포인터 가속 때문으로 추정.
- 결론: 이동량만 더하는 추적(dead reckoning)으로는 정확히 누를 수 없다. **방송 프레임에서 포인터를 찾아 목표와의 차이를 다시 보내는 폐루프 방식**으로 간다. 방송 익스텐션은 프레임을 이미 갖고 있으므로 맥 없이 아이폰 안에서 할 수 있다.
- 맥에서 USB 시리얼 포트를 새로 열면 보드가 재시작해 BLE가 끊긴다. 브리지로 포트를 한 번만 연다. 충전 전용 마이크로 USB 케이블로는 보드가 인식되지 않았다.

### 폐루프 이동과 클릭 (2026-10-28, `tools/touch-seek.py`)

- 원인 두 가지를 고치자 같은 이동량이 매번 같은 거리로 측정된다(20 → 17.1px, 6 → 4.6px, 150 → 142.6px).
  - 펌웨어: 보고서 간격 8ms → 15ms, notify 실패 시 재시도. 버려진 보고서 0개.
  - 방송 익스텐션: fps 제한이나 인코딩 중이라 건너뛴 프레임이 화면의 마지막 모습이면 영영 안 보내지던 버그. 건너뛴 것 중 최신 1개를 들고 있다가 보낸다(`FramePipeline.trailing`). 미러링에서도 스크롤이 멈춘 뒤 조금 전 화면이 남던 문제였다.
- 이동량 1당 픽셀은 작을수록 줄어든다: 10 미만 0.76, 30 미만 0.86, 그 이상 0.95(590x1280 프레임, 추적 속도 최저).
- 폐루프 결과: 빈 배경 목표 6곳 모두 도착, 오차 최대 3.4px(약 2pt), 보정 1~2회, 0.7~1.8초.
- **클릭 동작 확인**: 앱의 "복사" 버튼을 포인터로 찾아가 클릭하자 복사 알림이 떴다.
- 남은 과제
  - 포인터가 글자, 아이콘 위에 있으면 색과 크기만으로는 못 찾는다. 이동 전후 프레임 비교 등 더 튼튼한 검출이 필요하다.
  - AssistiveTouch 버튼 같은 비슷한 회색 원이 있어서, 예상 위치에서 가장 가까운 후보를 고른다.
  - 맥 프로토타입을 방송 익스텐션(검출과 보정)과 ESP32 Wi-Fi 수신으로 옮기기.

### 글자, 아이콘 위에서 포인터 찾기 (2026-10-28)

- 이동 후 프레임에 반영되기까지 0.3~0.4초 걸린다. 그보다 빨리 읽으면 이전 위치를 읽는다(초기 측정 일부가 이 오류였다).
- 모서리 원점 후 같은 이동: `m 300 150`은 4번 모두 같은 위치, 다른 경로는 최대 ±20px 차이. 열린 루프만으로는 부족하다.
- 같은 걸음으로 갔다가 되돌아오면 제자리로 온다. 이를 이용한 **비켜놓기 검출**: 포인터를 오른쪽으로 약 73px 비켜놓은 프레임과 원래 프레임의 차이에서 원 모양을 찾고, 두 원 중 왼쪽을 원래 위치로 본다. 글자와 아이콘 위에서도 찾는다(사진으로 확인).
- 폐루프에 넣은 결과: 글자, 아이콘 위 목표 5곳 중 4곳 도착(오차 3px 이내), 2~5초. 크고 굵은 글자 위 1곳 실패.
- 남은 문제: 느림(비켜놓기 한 번에 1초 이상), 화면 내용이 바뀌는 중(영상, 지도)에는 차이 영상이 오염됨. 앱에 접속하는 순간 제목이 바뀌어 오검출한 사례도 있다.
- 펌웨어에 `g dx dy s`(축별 고정 걸음 이동) 명령 추가.

### Wi-Fi 명령 통로 (2026-10-28)

- 보드가 저장된 Wi-Fi에 붙은 뒤 서버의 8082 포트로 TCP 연결을 건다. 서버 주소를 비우면 게이트웨이(핫스팟이면 아이폰)로 건다. 1초마다 `hb`.
- Wi-Fi 설정: 저장된 Wi-Fi가 없거나 BOOT 3초 → "Tessync-Touch-Setup" AP, http://192.168.4.1. 설정 모드에서는 BLE를 켜지 않는다(같이 켜면 아이폰이 AP에 붙는 순간 재시작했다). BOOT를 누른 채 전원을 넣으면 업로드 모드라 쓸 수 없다.
- 응답 시간: 보통 7ms, Wi-Fi 절전(BLE와 같이 쓰려면 필수) 때문에 가끔 80~100ms.
- 큰 대각선 이동은 iOS 가속 때문에 예상의 75%만 가기도 한다. 큰 이동은 축별 60 걸음(1당 약 0.98px), 작은 보정은 한 번에 보낸다.
- 모서리 원점 직후 첫 이동이 크게 빗나간다(가로 441 기대 → 211). 마지막으로 확인한 위치에서 출발하는 게 낫다.
- 펌웨어 파티션은 huge_app(BLE + Wi-Fi + 웹서버가 기본 1.2MB를 넘는다): `arduino-cli compile --fqbn esp32:esp32:esp32:PartitionScheme=huge_app`.

### 아이폰 익스텐션 안에서 동작 (2026-10-28)

- `TouchLink`(8082 TCP), `PointerFinder`(색 검출, 비켜놓기 차이 검출, 누적합으로 원 크기 창 탐색), `TouchController`(폐루프, 마지막 위치 기억, 세로만).
- 프레임 복사: 인코딩 큐에서 축소 프레임(YUV)의 밝기, 색 평면을 복사한다(590x1280에서 약 1.1MB). 보드가 연결돼 있을 때만.
- 결과: 빈 곳 목표 정확히 도착해 클릭(7.9초, 5.4초), "복사" 버튼 클릭 성공(5.8초, 포인터가 근처면 3.9초).
- 맥 앱 내장 브라우저는 로컬 WebSocket을 막아서 플레이어 클릭은 `tools/touch-tap.py`로 대신 시험했다.
